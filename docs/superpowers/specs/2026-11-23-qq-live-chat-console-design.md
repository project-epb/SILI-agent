# SILI 聊天管理页

## 目标

让管理员在现有 Koishi 控制台查看各平台机器人实际收到和发出的聊天，手动发信，并从 QQ 会话管理相关的人和群。

## 范围

- 各平台已记录的活跃会话、平台筛选、实时消息、历史翻页、引用和常见消息元素。
- QQ 会话右上角菜单提供配置。群内可搜索有记录的发言者并打开用户配置。
- 以当前会话对应的机器人身份发送纯文本或引用回复。撤回两分钟内由该机器人发送的消息。

## 决定

1. 在现有 Koishi 管理控制台提供「聊天」页面，沿用登录和四级权限。左侧是带平台筛选的会话列表，右侧是聊天区，窄屏在两者之间切换。
2. 会话按最近一次收发排序。历史和新消息都来自 `channel_message`，按平台、机器人和频道隔离，沿用现有记录范围和保留时间。新记录保留适配器提供的频道名称和类型。旧记录缺少名称时使用频道标识。控制台连接推送活动信号，页面重新同步最新一页，滚动回看时保留位置。
3. QQ 的群配置和私聊配置沿用激活状态和功能覆写。用户面板复用频道管理的 Koishi 权限编辑与权限检查。成员列表来自 `qqbot_member`，只列机器人记录过的发言者。
4. 正文按允许的 Koishi 元素展示，链接和媒体只接受安全的网络地址。引用在同一会话内解析，超出记录范围的引用显示为不可用。
5. 发送必须按住发送按钮或回车满 600 毫秒。提前松开、失焦、切换会话或取消手势会中止。输入法选词和 Shift+Enter 不触发发送。服务端按平台和机器人定位已记录的会话，遵守该平台的服务权限，交给对应的 Koishi 适配器。QQ 群额外检查主动发送权限。发送失败时显示错误并保留草稿。
6. 点击消息的「引用」后在编辑框预览目标，可取消引用或长按发送。服务端在当前会话解析原消息，QQ 优先用保存的引用索引。引用不可用时保留草稿并报错。
7. 撤回和删除共用适配器的删除接口。界面要求确认，服务端重新检查消息归属、会话和两分钟时限。平台确认成功后，本地保留「已撤回」或「已删除」记录，清除正文并同步页面。失败时显示错误。

## 验收

- 各平台的新消息会更新会话列表和当前聊天，不同平台的同名频道互不串。翻页没有重复，同秒消息齐全，查看旧消息时新消息不会拉走滚动位置。
- 机器人发出的消息显示在右侧，每条都标注「本机器人」。
- 群聊里能找到指定成员并进入对应人的设置。配置刷新后显示真实保存结果。
- 短按或取消不会发送。按住达标只发送一次，成功后在会话记录里出现。群关闭主动发送时清楚说明原因。
- 引用只指向当前会话内可用的消息。两分钟内的本机器人消息可以确认撤回，其他消息没有撤回入口且服务端拒绝操作。
- 未登录或权限不足无法读取聊天和成员数据、接收活动信号或发送消息。
