# Wiki 入群验证（萌娘百科 + Fandom）

## Goal

萌娘百科的多个官方 QQ 群要由 SILI Official 审核入群申请，各群门槛不同（有账号即可、自动确认用户、指定用户组）。现有 `fandom-join-verify` 只服务 Fandom 一个群、按群严格一一对应，扩展为多站点、按 wiki 记绑定、按群配置门槛的通用插件，Fandom 群一并迁移。

## Scope

- In：插件通用化（多站点、绑定、门槛、人工审批）；`入群申请` 指令与按钮；萌娘百科验证页面（Template + Widget）；Fandom gadget 文案更新；`fandom_verify` 数据迁移。
- Out：解绑指令（换号、误绑由管理员直接改库）；萌百旧的 `User:<名>/QQHash` 机制（另一个 onebot 仍在用，不动）；新人群（游客可进，不接入）；按群成员接口判断旧 QQ 是否已退群（SILI 无该接口权限）。

## Decisions

1. **验证码机制沿用 Fandom 版**：浏览器生成 16 位 Crockford base32 随机码，把 `时间戳#sha1(时间戳#随机码)` 写进用户子页，入群答案为 `<wiki 用户 ID>-<随机码>`，有效期 2 小时。验证页名按站点配置：萌百 `User:<名>/QQVerify`，Fandom 保持 `User:<名>/qq-hash`。
   Why：机制已在 Fandom 生产验证；萌百旧的 `QQHash` 页仍被别人的 onebot 使用，不能覆盖。

2. **验证码在有效期内只能用一次**。用掉 = 以页面哈希为主键原子插入一条记录；插入失败（并发或重放）时，若申请人已按 openid 绑定到同一 wiki 账号，按已绑定处理，否则提示「这个验证码已经用过了」转人工。
   Why：主人明确要求一次性；原子插入让同一码并发申请多个群时只有一次真正消耗。

3. **绑定按 wiki 记，不按群记**：`(bot selfId, 申请人 openid, wiki)` → wiki 用户 ID。同一 bot 下同一个人在各群的 member openid 相同（已在生产库核实），所以绑定后申请该 wiki 的其他群不需要再生成验证码，答案可随便填。
   Why：一个人通常要加多个萌百群，管理组群常是后来才够格加入。

4. **绑定规则**：
   - 一个 QQ 只认**最近绑定**的 wiki 账号：同一 QQ 交来另一个账号的有效码，自动换绑。
   Why：wiki 编辑者在意社区身份，换绑说明真打算换号；第二个账号多半是 bot 小号。
   - 一个 wiki 账号可对应多个 QQ，但账号**已绑过别的 QQ 又带来新 QQ** 时转人工（提示请确认不是盗用），管理员同意后追加绑定，旧绑定保留。
   Why：QQ 多开常见，但首次出现需要人看一眼防盗用。
   - 答案里没有有效码时：已绑定就按绑定账号走，未绑定转人工并写明原因。

5. **门槛按群配置，每次申请现场查 wiki**：配置为「满足任一用户组」（`list=users&usprop=groups|blockinfo`，含 `autoconfirmed` 等隐式组），空表示只要绑定有效。**当前被封禁的账号一律转人工**。门槛不存库。
   Why：权限会变动，撤权、封禁后再申请高门槛群要过不了。「编辑者」= 有账号即可：保存验证页本身就是一次编辑。
   群可另设「临时用户组最短持有天数」：命中的组是永久的（`groupmemberships` 的 `expiry` 为 `infinity`）直接满足；是临时的，按用户权限日志里最近一次该组从无到有的时间计算持有天数，不足或查不到转人工。续期不重新计时。
   Why：维护组群只收「临时用户组已持有 7 天，或持有永久用户组」的人（实习维护姬 7 天后才可加群）。

6. **群与门槛**（萌百 zh 站）：

   | 群 | 门槛（任一） |
   |---|---|
   | 编辑讨论群 Pro / Plus / Promax、翻译互助群 | 绑定有效即可 |
   | 限水编辑交流群 | `autoconfirmed` |
   | 编辑组负责人/外联群 | `staff`、`sysop` |
   | 技术编辑群 | `techeditor`、`interface-admin`、`staff`、`sysop` |
   | 界面管理员群 | `interface-admin` |
   | 维护组群 | `staff`、`sysop`、`patroller`；临时组须持有满 7 天 |

   Fandom 中文群：绑定有效即可。wiki 上没有对应用户组的身份（编辑组负责人、机器人所有者）落入「门槛不够」，转人工。SILI 必须是该群管理员才收得到申请、能代为同意。
   群配置写在 v5 profile 里，本地测试群通过环境变量追加。
   Why：openid 不是机密，门槛属于业务规则，应随代码评审；Noir 的群 openid 与 SILI Official 不同。

7. **通过就自动同意，失败从不自动拒绝**。转人工的情况：码无效且未绑定、多 QQ 首次出现、门槛不够、封禁、查询出错、同意接口失败。

8. **人工审批：按钮 + `入群申请` 指令，共用一套处理逻辑**。
   - 待审核通知下挂「通过」「拒绝」回调按钮，`permission.type = 1`（仅群管理者可点），按钮 `data` 只放动作和申请人 openid；拒绝带二次确认弹窗，不拉黑。按钮在 QQ 侧约 30 分钟失效。
   - `channel.join-request`（别名 `入群申请`）：列出本群待处理申请，每条现场重新校验并附新按钮，任何人可用。子指令 `通过 <编号>`、`拒绝 <编号> [理由]`，编号取申请人 openid 前 6 位。指令不设 `authority`，在 action 内检查 `session.event.member.roles`，非 `owner`/`admin` 回复「只有群管理员可以审批入群申请」。
   - 待处理申请一律现拉 `join_request_list`（含答案、`join_request_id`），不自建待审表；同意/拒绝直接调 `approveJoinRequest(群, openid, { op, join_request_id })`。
   Why：成员接口无权限，但消息事件带 role、按钮权限由 QQ 执行；`join_request_list` 已实测可用且申请长期有效；适配器的 `handleGuildMemberRequest` 依赖内存 Map，重启后失效。
   - 人工同意时：答案里的码与页面哈希对得上（不看有效期）且未被别人用掉，就用掉码并写绑定；否则只同意不绑定。
   Why：管理员可能在码过期后才处理，但页面哈希仍证明账号归属。

9. **群通知**：每个申请一条原生 Markdown 消息，沿用 Fandom 版的通过/待审核格式和被动回复→主动消息的发送方式；文案里的站点名按配置（「萌娘百科」「Fandom」）。

10. **wiki 侧页面**：萌百用 `Template:QQVerify` + `Widget:QQVerify`（现代 JS，哈希用 `crypto.subtle`）；Fandom 继续用 ES3 gadget。源码放仓库、手动部署。非自动确认用户在萌百不能直接用 API 保存，改为向 `action=submit` 提交预填好的编辑表单（打开预览）、由用户手动保存，验证码在打开编辑页前就生成并显示。不用 preload：它只对新建页面生效，重新生成时页面已存在。萌百的编辑审核是先发后审，待审修订照样能被 SILI 读到。两站都保留 sysop 手动核对框。
    Why：萌百旧 Widget 已证明新用户需要这条路。

11. **加群码说明文案**，两站一致，显示在加群码旁并在复制时提示（「一次性」加粗，「请勿分享给其他人」加粗斜体）：

    > 这是你的**一次性**加群码，***请勿分享给其他人***。
    > 请在2小时内使用，将其完整粘贴到加群答案中即可。
    > 如有遗失，可回到这里重新生成（旧码作废）。

    「旧码作废」由机制保证：验证页只存最新一次生成的哈希，SILI 只读最新版本。

12. **数据**：新表 `wiki_join_code`（页面哈希主键、wiki、wiki 用户 ID、selfId、openid、时间）记录用掉的码；新表 `wiki_join_binding`（wiki、wiki 用户 ID、wiki 用户名、platform、selfId、openid、绑定时间、来源：自动/人工）。`fandom_verify` 现有记录迁入两张新表后弃用。
    Why：码的消耗与身份绑定生命周期不同（换绑会改绑定、但码永远不能再用）。

13. **wiki API 用 `mediawiki/utils` 的 `useApi()`**。
    Why：萌百需要 UA token 和 bot 登录，这些已在其中配置，生产与本地 `.env` 都有 `MW_BOTPASSWORD_MOEGIRL_*`。

## Acceptance

- 界面管理员群（或沙盒群配成同等门槛）：界管账号生成答案申请入群，自动同意，`wiki_join_binding` 与 `wiki_join_code` 各多一行。
- 同一 QQ 再申请另一个已配置的萌百群，答案留空，按绑定自动同意（门槛满足时）或转人工（不满足时）。
- 同一答案换一个 QQ 申请，提示码已用过、转人工。
- 已绑定账号带新 QQ 和新码申请，转人工并提示疑似盗用；管理员点「通过」后入群并追加绑定。
- 同一 QQ 带另一账号的有效码申请，自动换绑。
- 封禁账号申请任何群都转人工。
- 非群管点按钮无效；非群管发 `入群申请.通过` 被拒；群管 30 分钟后用 `入群申请` 重新列出并点按钮能通过。
- SILI 重启后，重启前的待处理申请仍能通过按钮或指令处理。
- 萌百非自动确认用户能通过预填的编辑页生成并保存验证码（包括页面已存在时重新生成），SILI 能验证。
- Fandom 群迁移后，旧记录对应的用户再申请时按绑定识别。
