# 隐式接话（一阶段）

## Goal

群友不 @ SILI、也不以 SILI 的名字开头，但其实是在回答 SILI 的问题，或者在向 SILI 提请求。现在这类消息会被漏掉，SILI 一直不吭声。一阶段要让 SILI 判断出这句话是对自己说的，然后接上。

## Scope

- In
  - 记录 SILI 每条出站消息的起因。
  - 引用 SILI 的消息直接进入 chat。
  - 白名单群的旁听分类器：本地规则先过滤，通过的再按批调用 decisions 接口，判定后唤醒 chat。
  - chat 获得「看了但不回」的能力。
  - 离线回放评测脚本。
- Out
  - 主动接群梗、附和调侃、迫害吉祥物。分类器会识别「在议论 SILI」，但只记日志不唤醒。
  - 群设定（梗、吉祥物）的编写与注入。
  - 发送前的润色。
  - v4 profile。

## Decisions

1. **只在 v5 profile 生效，只对 QQ 群生效。**
   Why: 全量消息入库（`channel_message`）和群共享会话（`resolveConversationScope` 中 `shared`）目前只在 v5 的 QQ 群成立。

2. **`channel_message` 新增 `origin` 字段，记录 SILI 出站消息的起因。** 取值如下：

   | 值 | 含义 |
   | - | - |
   | `chat` | LLM 回复 |
   | `command:<name>` | 指令输出 |
   | `teach` | Teach 暗号触发 |
   | `push` | 定时或被动推送 |
   | `other` | 其他 |

   `chat` 还要附带两项：这次回复针对的用户，以及这条回复是否以提问结尾。入站消息的 `origin` 为空。起因在发送时写入：chat 发送时自己写明；其余由 `before('send')` 根据 `session.argv.command` 推断。
   Why: 群友对 SILI 发言的反应取决于这句话的起因。评论 pixiv 结果不是在跟 SILI 说话，回答 SILI 的提问才是。NapCat 和平台的历史记录里都没有这项信息，只能在发送时记下来。

3. **引用 SILI 的消息直接进入 chat，不经过分类器。** 判定条件是 `session.quote` 的作者是 SILI 自己。触发方式与 @ 相同，都走 FallbackHandler 的兜底。
   Why: Koishi 的 `stripped.appel` 只认句首 @ 和句首昵称，引用 SILI 的消息目前不会触发 chat。这种情况用规则就能确定，不该花分类费用。

4. **用 feature 服务做白名单。** 注册一个旁听子指令，`featLevel` 设得比激活等级高，因此默认关闭；群管理员用 feature 指令按群打开。这个子指令本身用来查看本群的旁听状态和最近几次判定结果。
   Why: 复用现成的按群开关和权限，不用新建表。
   Rejected: 新建旁听配置表 —— 和 feature 的覆盖记录重复。

5. **先用免费的本地规则过滤，只有通过的批次才调用分类器。** 一批新消息至少满足下面一条才送去分类：
   - SILI 在本群最近 10 分钟内有 `origin=chat` 的发言。
   - 消息里出现 SILI 的名字或别名，但不在句首。

   两条都不满足就直接把游标推进到这批之后，不调用。
   Why: 用户主要担心活跃群里分类的 token 消耗。SILI 没开口的群、刷屏但和 SILI 无关的群，都应该接近零成本。

6. **调度：按群合批、串行执行。** 规则参照橘波特：
   - 每个群维护一个「已判断到哪一条」的游标，同一个群同时只跑一个分类请求，跑的过程中进来的消息合到下一批。
   - 等待时长：SILI 3 分钟内说过话等 3 秒，15 分钟内说过话等 10 秒，否则等 30 秒。
   - 已被 Koishi 处理的消息（指令消息，以及走了直接触发的 @、点名、引用）既不参与判定，也不出现在上下文里。
   - 直接触发会把游标推进到当前位置。分类结果返回时，如果它覆盖的消息已经被直接触发处理过，这次结果作废。

   Why: 合批可以减少调用次数。橘波特踩过一个坑：上下文里混着指令消息，模型会误以为有人在叫自己。

7. **输入格式。** 在 `read-channel-history` 格式化器的基础上扩展，每条消息带这些信息：
   - 消息编号
   - 与上一条消息的时间间隔
   - 发言人：昵称、id、群角色；SILI 的发言标为「(你)」，并附上 `origin`
   - 引用的是哪一条消息、@ 了谁
   - 图片和表情折成占位标记，连续复读合并为一条

   背景消息和本批新消息分成两个区块。说话人用原始昵称，不做脱敏改写。
   Why: 首轮评测用的简略格式丢掉了起因、角色和节奏这几项判定依据。这些群聊本来就会作为 chat 的输入发给同一个 provider，脱敏不会减少任何暴露，反而让评测失真。

8. **分类器走 ZenMux 的 decisions 类接口，单选题，按整批判断。** 选项如下：

   | 选项 | 含义 | 处理 |
   | - | - | - |
   | `followup` | 在接 SILI 的话 | 唤醒 |
   | `request` | 在向 SILI 提出具体请求 | 唤醒 |
   | `about_sili` | 在议论 SILI，但不是对它说话 | 只记日志 |
   | `resolved` | 问题已解决或在收尾 | 不唤醒 |
   | `unrelated` | 群友之间的对话 | 不唤醒 |
   | `unclear` | 证据不足 | 不唤醒 |

   `followup` 与 `request` 的概率之和达到门槛时唤醒。每次判定都记日志，内容包括批次范围、各选项概率和是否唤醒。
   Why: 用户担心普通 LLM 判定的成本；decisions 类接口便宜也快。一阶段唤醒后由 chat 自己从整批消息里找要接的那一句，所以不需要分类器输出消息编号。
   Rejected: 用普通 LLM 输出 JSON（橘波特的做法）—— 在活跃群里成本明显更高。

9. **分类器触发的唤醒走 chat 的内部入口。**
   - 额度按群计，不受 chat 每人每分钟一次、最多 10 次的限制。
   - 唤醒时把这批新消息、命中的选项及概率一起传给 agent。
   - 唤醒后 agent 仍然可以选择不说话。

   Why: 这样能复用 chat 已有的群共享会话、记忆、权限和 agent loop。被叫醒并不是某个群友主动调用了 chat，所以不应该占用个人额度。

10. **加一个 `maySkip` 标记，决定 chat 能不能沉默。** 只有当本群开着旁听、而且分类器最近一次调用成功时，`maySkip` 才为真。
    - 为真时，agent 多一个「不回复」出口，并配上指引：明确的提问和请求必须回答；随口调侃可以先放着。
    - 选择不回复时，这一轮作为「看到了，选择不回」写进会话历史。后续相关消息会再次唤醒 SILI，那时 agent 能看到自己已经忍过几次。
    - `maySkip` 为假时，维持现有行为：@ 必回。

    Why: 用户希望 SILI 被 @ 一句也能不理，等攒多了再回应，即「骂一句忍了，这么多人骂我我不忍了」。但只有分类器正常工作时，后续消息才能把 SILI 重新叫醒；分类器坏了还允许沉默，SILI 看起来就是坏掉了。

11. **分类器出错不影响现有功能。**
    - 旁听插件旁路运行：中间件只把消息放进队列，从不等待分类结果；请求设超时，所有异常吞掉并写日志。
    - 指令、@、点名和引用 SILI，都不经过分类器。

    Why: 用户的要求是：分类器坏了，SILI 的指令和直接触发必须照常可用。

12. **离线回放评测是一阶段的第一步，先于全部实现。** 分类模型、唤醒门槛、输入格式和选项描述都以评测结论为准；`origin` 要记录哪些字段，也在评测之后再定。
    - 脚本放在 `.debug/`，与线上共用同一个格式化器和同一套过滤规则。
    - 数据从生产库只读导出，取萌百编辑群的 `channel_message` 和 chat 会话记录。
    - 历史消息还没有 `origin`，用启发式规则补齐：SILI 消息前几秒内有人发了带前缀的指令，记为 `command:<name>`；内容能和 chat 会话中的 assistant 回复对上，记为 `chat`；其余记为 `other`。
    - 样本按第 5 条的过滤规则切成批次，同时统计每个群每天的分类调用次数，作为成本依据。
    - 强模型先打草稿标签，由用户逐条确认。真实样本和构造的难例分开统计。
    - decision 调用便宜，所以模型、输入格式、判定说明、选项描述做小规模全组合对比。
    - 由用户标注正确选项。
    - 用评测结果选定模型（候选 Clef Flash、Jev）和唤醒门槛。

    Why: 首轮评测用的是改写过的短样本，判定规则还偏向沉默，结论不能沿用。

## Acceptance

- SILI 的每条出站消息在 `channel_message` 里都有 `origin`；chat 回复的 `origin` 带有针对的用户和「是否以提问结尾」。
- 群友只引用 SILI 的消息、不 @，SILI 照样接话。
- 未开旁听的群：不调用分类器，行为与现在一致。
- 开了旁听的群：SILI 问了一个问题，有人不 @ 直接回答，SILI 能接上；群友之间自聊，或者只是在议论 SILI，SILI 保持沉默，判定日志里能看到对应的选项和概率。
- SILI 超过 10 分钟没说话、群里也没人提到她的名字时，不发生任何分类调用。
- 把分类器的接口地址改成不可用：分类失败只写日志；指令、@、点名、引用全部照常；被 @ 时 SILI 必回。
- 分类器正常时，被 @ 的一句随口调侃，SILI 可以不回；之后再有相关消息时，SILI 能看到自己之前选择了沉默。
- 回放脚本能从 `channel_message` 生成带标注格式的样本，对候选模型输出每个选项的概率和延迟。
