# 群聊共享会话

## Goal

SILI 的 LLM 会话现在按用户划分：同一个群里，每个人跟 SILI 各聊各的，A 刚说过的事 B 问起来 SILI 不知道，她也不记得自己在群里说过什么。改成一个群共享一个会话，让 SILI 真正「在群里」，并能借群聊历史熟悉各群的说话习惯。

## Scope

- In：QQ 群的会话归属、上下文组装、回复中途的插话（steer）、压缩触发、群会话里的个人记忆。
- Out：私聊的会话归属（仍是一人一个）；群记忆文档（第二期）；把群消息整段放进上下文。

## Decisions

1. **所有 QQ 群切到共享会话，私聊不变。** 不做按群开关。

2. **群会话挂在群上。** 群的当前会话 ID 存在 `channel` 表，与用户身上的 `openai_last_conversation_id` 同一做法；会话归属由用户改为「用户或群」。
   Why：沿用现有会话表和历史表，不另建一套存储。

3. **上下文只放触发 SILI 的那条消息。** `turn_context` 增加一个字段：距她上次在本群发言，群里又过了几条消息。只给数字，prompt 里不引导她去翻历史；`read_channel_history` 照常在工具列表里，用不用由她自己判断。
   Why：整段群聊塞进上下文会迅速膨胀，大部分内容与 SILI 无关。提示她去翻，她就会每轮都翻，注意力被拉偏。
   Rejected：每轮附上最近 N 条群聊——量难定，且大多用不上。

4. **说话人写进每条用户消息的 `turn_context`。** 共享会话里有多个人，模型靠它区分是谁在说话、该怎么称呼。

5. **插话用 steer，注入工具结果。** SILI 正在回复时，同一群又有消息触发她（包括同一个人），不中止、不排队，而是在本轮下一个工具结果的末尾追加该消息的 `<turn_context>` 和 `<user_message>`，下一次迭代时模型看到。本轮已经在输出最终回复、没有后续工具调用时，等本轮结束后立即开新一轮处理积压的消息。群会话不再使用按用户的中止重来。
   Why：追加到工具结果不改变消息结构，兼容各家 API 对消息顺序的要求；用户发言本来就包在 XML 标签里，模型容易区分。

6. **工具结果里的协议标签一律转义。** 外部内容（网页、群聊历史等）里出现的 `<user_message>`、`<turn_context>` 等协议标签，进入工具结果前先转义，只有 steer 注入的才是原样标签。
   Why：否则网页或群友消息里伪造的标签会被当成真实插话。

7. **群会话不预先注入个人长期记忆。** 需要时由 SILI 调 `read_user_memory` 读当前说话人的记忆。
   Why：防止 A 的私人记忆在群里被说漏给 B。

7a. **群会话不触发后台记忆整理（memory fork），只在私聊触发。** SILI 在群里仍可调 `save_user_memory` 记下当前说话人明确交代的事。
   Why：后台整理拿整段会话历史给某人写记忆，群会话里有所有人的话，会把别人说的事写进这个人的记忆。

8. **压缩按上下文大小触发，群聊与私聊统一。** 以上一轮 provider 返回的 `promptTokens` 作为上下文大小：
   - 超过 **256k** 时，下一轮开始前先压缩；
   - 闲置 **6 小时**且超过 **24k** 时，后台主动压缩一次。
   压缩沿用 `SummaryCompactor`：生成摘要，开新会话，`prev_session_id` 指回旧会话。两个阈值和闲置时长都是配置项。群会话不再因空闲超时开新会话。
   Why：DeepSeek 的 prompt 缓存可以保留很久，过早压缩反而浪费缓存；闲置压缩是为了话题结束后整理上下文。`deepseek-v4-flash` 上下文窗口约 1M，256k 留有余量。
   Rejected：按用户消息条数（现在的 50 条）触发——群里条数涨得快，与实际上下文大小关系不大。

8a. **历史加载上次压缩以来的全部消息，不再按轮数截取。** 去掉 `historyTurnCount` 的窗口和查询的行数上限，由压缩控制总量。
   Why：截取窗口会让上下文永远到不了压缩阈值；窗口每滑动一次前缀就变，prompt 缓存失效。完整加载时前缀在两次压缩之间保持稳定。

8b. **群里重置会话（「聊点别的」/`llm.reset`）只限群主、群管理员或 SILI 权限 2 以上。** 其他人发会得到提示，会话不变。
   Why：共享会话被重置等于清空所有人的上下文。

9. **群记忆放到第二期。** 每群一份有长度上限的记忆文档（群梗、谁是谁），先把共享会话和 steer 跑稳。

## Acceptance

- 群里 A 跟 SILI 说了一件事，B 随后 @ SILI 问起，SILI 知道。
- SILI 回复中（正在调工具）时 B @ 她，B 的消息出现在本轮后续处理中，SILI 能一并回应；她已在输出最终回复时，B 的消息在本轮结束后立即得到处理。
- 工具结果里伪造的 `<user_message>` 不会被当成插话。
- 群会话的系统提示和首轮不包含任何个人长期记忆。
- 上下文超过 256k 时，下一轮先压缩；闲置 6 小时且超过 24k 时自动压缩，摘要会话的 `prev_session_id` 指向旧会话。
- 私聊行为除压缩触发方式外不变。
