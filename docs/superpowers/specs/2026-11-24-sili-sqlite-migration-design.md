# SILI 生产 MongoDB → SQLite 一次性迁移

## 目标

将单实例 SILI 的主数据库切到 SQLite。迁移在停止业务写入的窗口内完成。迁移前已提交的数据完整保留。切换后短时间内若需回滚，允许丢失这段时间产生的少量新数据。

## 范围和决策

- 只迁 SILI 的主数据库。Linux 虚拟机磁盘、附件缓存、对象存储和 QQ 适配器继续走各自的部署路径。
- 使用 Noir 已验证的官方 Koishi SQLite 插件 `4.6.0`，锁定兼容的驱动和 SQL 工具版本。SQLite 数据文件放在生产持久卷，数据库后端使用显式配置。切换代码上线时先使用 MongoDB。
- 任意时刻只允许一个业务实例处理生产写入。停机时冻结旧库，最终导入完成后切换应用，迁移期间没有双写。
- MongoDB 是 standalone，最终备份在冻结写入后生成。备份包含全库集合，包括旧表和 MongoDB 内部元数据。当前业务模型逐表导入，旧表及未建模字段保存在可恢复的原始归档中。发现未归类的表或字段时停住核对。 [MongoDB 备份一致性](https://www.mongodb.com/docs/database-tools/mongodump/)
- 首次切换使用 SQLite 的 `DELETE` 日志模式，并用目标模式实测备份和写入延迟。官方驱动内置的 SQLite `3.39.3` 处于官方所列 WAL 并发写入和 checkpoint 故障影响版本范围内。 [SQLite WAL 说明](https://www.sqlite.org/wal.html#the_wal_reset_bug)
- SQLite 备份使用宿主 SQLite 在线备份接口。先写临时快照，成功后做完整性检查，再归档、上传并按保留规则清理。切换窗口暂停旧备份任务。SQLite 备份通过恢复验证后，将每天 04:00 的任务切到 SQLite。回滚时恢复 MongoDB 备份任务。备份包含应用令牌和身份数据，落盘和远端均使用受限读取。 [SQLite 在线备份](https://sqlite.org/backup.html)

## 切换前准备

1. 在 Noir 用最终候选镜像实测真实 QQ 收消息、发回复和两条消息入库。用与生产相同的版本、日志模式和挂载方式。
2. 用一份生产备份在隔离环境演练全量导入和回滚，记录从关入口到服务恢复的实测耗时，验证新旧备份可以恢复。演练包含切换后产生少量 SQLite 新记录，再恢复冻结的 MongoDB。
3. 导入工具输出集合归类、逐表行数、主键集合和字段差异。校验用户、绑定、群激活、消息、LLM 会话、订阅、计划任务和自增主键。对齐已有格式差异，包括旧消息缺少撤回标记和非有限时间值。每项转换都要有计数和明确规则。
4. 准备旧镜像、配置、MongoDB 数据卷和入口切换方式。尝试窗口避开 MongoDB 和 Linux 虚拟机的定时备份。冻结计划任务、主动推送和其他写入口在开流验证期间的执行。

## 生产切换

1. 关闭业务入口并停止旧 SILI，确认数据库写入源都已停止。启动停机计时。HTTP 写入口返回维护状态。QQ 停机期间消息能否重投以平台行为为准。
2. 生成最终 MongoDB 归档，验证备份完成和完整性。从这份归档导入一份新的 SQLite 文件。完成主键、数据和索引核对后，将文件放入生产持久卷。
3. 启动 SQLite 版 SILI，立即核对启动、数据库、后台探测及真实 QQ 命令入库。切换程序记录所在阶段；任何一处失败，执行对应阶段的回滚。
4. 验收通过后现场核对已有群和新消息的读写，再验证 SQLite 在线备份及独立恢复。

## 回滚

停止 SQLite 版 SILI，保留 SQLite 文件以供排查，恢复切换前的配置和 MongoDB 数据，再启动 SILI 并恢复 MongoDB 备份任务。切换后短时间内的 SQLite 新写入可以丢失。核对 QQ 网关、命令回复和备份任务归属。

## 验收标准

| 项目 | 通过条件 |
| --- | --- |
| 数据 | 现用集合归类完成。逐表行数及主键集合一致，未解释的字段差异为零。归档可恢复旧表及历史字段。新建用户或会话不撞旧主键。 |
| QQ | 真群 `/ping` 收到回复，SQLite 有同一会话的入站和出站记录。重复投递只保留一条。历史分页、引用、`@` 查询、撤回和已激活群访问通过。 |
| 业务 | 后台能登录，历史页可用。一次已有会话的 LLM 对话能接续；如启用 GitHub 订阅，用测试仓库核对回调和一次推送。 |
| 备份与性能 | SQLite 备份能在独立目录恢复，`integrity_check` 返回 `ok`，恢复数据对账通过。同机用相同消息回放测正常与备份期间的读写。建议每项 P95 不超过 MongoDB 基线加 20% 或 5 ms，取较宽者。数据库错误和写入丢失均为零。 |
| 停机与回滚 | 演练记录迁移停机时间，以及发出回滚指令到旧服务重新应答的时间。回滚恢复目标为 2 分钟。迁移停机目标为 5 分钟。切换过程中，剩余时间只够回滚时立即回切。 |
