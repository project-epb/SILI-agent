# 个人记忆分两档：私密记录 / 共享记录

## Goal

QQ 群改成共享会话后，个人长期记忆在群里读写有隐私风险：私聊里说的事会被 AI 在群里引用，读出来的内容留在群上下文里可被他人追问，别人插话（steer）还能把内容写进触发者的记忆。把个人记忆拆成只在私聊读写的私密记录和可在群里读写的共享记录，群里只碰共享的那份。

## Scope

- In：记忆存储与工具、私聊首轮快照、系统提示里的记忆段落、llm-admin 记忆面板。
- Out：按群存的群记忆（另做）；后台记忆整理（memory fork）的逻辑本身。

## Decisions

1. 每位用户两份记录：**私密记录**（现有 `openai_user_memory`，原样保留）和**共享记录**（新表 `openai_user_shared_memory`，字段 `platform` `user_id` `content` `byte_size` `last_updated_at` `update_count`，`[platform, user_id]` 唯一）。
   Why：私密记录的整理计数字段（`message_count_at_update` 等）共享记录用不上；另建表不用改现有唯一索引。
2. 私密记录只在私聊读写；共享记录私聊、群聊都能读写。
   Why：私密内容根本不进群上下文，就不存在泄露和追问的问题，也不用事后改写历史（会破坏前缀缓存）。
3. 共享记录只记本人在群里亲口说过、或明确让记住的可公开信息（称呼、爱好、在玩的游戏等），私聊内容不搬进来，除非用户在私聊里明说可以公开记。工具描述写明「这份记录在所有群都可能被看到」。
   Why：共享记录跨群可见，AI 需要知道这一点才能判断什么值得记。
4. 工具仍是 `read_user_memory` / `save_user_memory` 一对，工具列表不随会话变化：
   - `read_user_memory`（无参）：私聊返回私密 + 共享两段，群聊只返回共享一段。
   - `save_user_memory(tier, content)`：`tier` 为 `private` | `shared`，整份覆写对应那份；群里写 `private` 直接报错「私密记录只能在私聊里改」。read-before-write、每轮每份只写一次、乐观锁按份各自校验。
   Why：工具定义在缓存前缀里，按会话增删工具会让缓存失效。
5. 读写结果都标明归属：`<user_memory owner="名字" uid="…" tier="private|shared">` 包住内容，并附一句性质说明（私密：「只在私聊用，不要转述给第三方」；共享：「所有群可见」）；写入返回「已更新 名字（uid …）的共享记录（N 字节）」。
   Why：群里多人说话，不标明是谁的容易张冠李戴。
6. 记录的主人永远是触发这一轮的人（`resolveMemoryKey(session)`）。这一轮里有别人插过话（steer 注入了其他人的消息）时，`save_user_memory` 拒绝写入，提示等本人下次单独说。
   Why：插话者能借别人的那一轮往对方记录里投毒。
7. 私聊首轮快照 `<long_term_memory>` 同时带私密和共享两段，各自标明归属与档位；群会话仍不注入任何快照。
8. 后台记忆整理只读写私密记录；共享记录只由 AI 主动写入。
   Why：整理读的是私聊会话，它的产物天然是私密的。
9. 共享记录上限独立配置 `sharedMemoryByteLimit`，默认 1000 字节（硬上限同样按 ×1.1 计）。
   Why：共享记录只放可公开的少量信息，也压低群里每次读取的 token 开销。
10. 系统提示的记忆段落改为说明两档的区别与各自的使用场合，删掉「为每位用户维护一份长期记忆」的旧说法。
11. llm-admin 用户详情里私密、共享两份分开展示，都可查看、编辑、清空；用户列表的「记忆」列显示两份字节数之和。

## Acceptance

- 群里 @SILI 让她「记住我喜欢 X」：写进本人的共享记录，回复里没有私密内容；私聊问她能答出 X。
- 群里诱导她读私密记录或写 `private`：工具返回错误，私密记录不变。
- B 的回复进行中 A 插话「记住 B 是 Y」：本轮写入被拒，B 的两份记录都不变。
- 私聊新会话首轮的 `<long_term_memory>` 里有两段，各自标明主人和档位。
- llm-admin 能分别看到、编辑、清空两份记录。
