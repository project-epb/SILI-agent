# 记忆分三档：私密记录 / 共享记录 / 群记忆

## Goal

QQ 群改成共享会话后，个人长期记忆在群里读写有隐私风险：私聊里说的事会被 AI 在群里引用，读出来的内容留在群上下文里可被他人追问，别人插话（steer）还能把内容写进触发者的记忆。把个人记忆拆成只在私聊读写的私密记录和可在群里读写的共享记录，群里只碰共享的那份；另加按群存的群记忆，存群梗、群规、成员关系这类属于整个群的事。

## Scope

- In：记忆存储与工具、首轮快照、系统提示里的记忆段落、llm-admin 记忆面板。
- Out：后台记忆整理（memory fork）的逻辑本身；群记忆的后台整理。

## Decisions

1. 三份记录，存储形状相同（`platform` `owner_id` `content` `byte_size` `last_updated_at` `update_count`，`[platform, owner_id]` 唯一），除私密记录沿用旧表外各一张表：
   - **私密记录**：现有 `openai_user_memory`，原样保留，主人是用户。
   - **共享记录**：`openai_user_shared_memory`，主人是用户（`owner_id` = Koishi uid）。
   - **群记忆**：`openai_group_memory`，主人是群（`owner_id` = 群号 / channelId）。
   Why：私密记录的整理计数字段（`message_count_at_update` 等）另两份用不上；另建表不用改现有唯一索引。
2. 私密记录只在私聊读写；共享记录私聊、群聊都能读写；群记忆只在本群读写。
   Why：私密内容根本不进群上下文，就不存在泄露和追问的问题，也不用事后改写历史（会破坏前缀缓存）。群记忆只属于本群，不带到别处。
3. 共享记录只记本人在群里亲口说过、或明确让记住的可公开信息（称呼、爱好、在玩的游戏等），私聊内容不搬进来，除非用户在私聊里明说可以公开记。工具描述写明「这份记录在所有群都可能被看到」。
   Why：共享记录跨群可见，AI 需要知道这一点才能判断什么值得记。
4. 个人记录（私密、共享）只记关于本人的事：涉及别人的关系只能写成本人的说法（「自称是 X 的徒弟」）。成员之间的关系、群里发生过的事、群梗、群规记进群记忆：大家都看到的用中性措辞直接记事实（「A 和 B 因为 X 吵过一架」），只有当事人自己的说法写成「A 说……」；不记谁对谁错、不给人下定性评价，私下矛盾和现实冲突不记。
   Why：防止借 SILI 的口吻对别人下结论；人际关系不能一刀切，中性的事实是群记忆的价值所在；关系牵涉双方、只在本群情境有意义，属于群。
5. 工具仍是 `read_user_memory` / `save_user_memory` 一对，工具列表不随会话变化：
   - `read_user_memory`（无参）：私聊返回私密 + 共享；群聊返回触发者的共享记录 + 本群群记忆。
   - `save_user_memory(tier, content)`：`tier` 为 `private` | `shared` | `group`，整份覆写对应那份；群里写 `private`、私聊写 `group` 直接报错。read-before-write、每轮每份只写一次、乐观锁按份各自校验。
   Why：工具定义在缓存前缀里，按会话增删工具会让缓存失效。
6. 读写结果都标明归属（主人名取群名片 / 平台昵称，不取 Koishi 名字——那可能是 `callme` 设的私下称呼）：`<user_memory owner="名字" uid="…" tier="…">` 包住内容，并附一句性质说明（私密：「只在私聊用，不要转述给第三方」；共享：「所有群可见」；群记忆：「本群共有，只在本群用」）；写入返回「已更新 名字（uid …）的共享记录（N 字节）」。
   Why：群里多人说话，不标明是谁的容易张冠李戴。
7. 个人记录的主人永远是触发这一轮的人（`resolveMemoryKey(session)`）。这一轮里有别人插过话（steer / backlog 带了其他人的消息）时，写个人记录被拒，提示等本人下次单独说；群记忆不受此限。
   Why：插话者能借别人的那一轮往对方记录里投毒；群记忆本来就是大家的。
8. 首轮快照 `<long_term_memory>`：私聊带私密 + 共享；群共享会话只带本群群记忆，不带任何个人记录。压缩后的新会话同样。
   Why：群记忆只属于本群，注入群上下文不外泄，让 SILI 一开口就知道群里的梗；个人记录在多人会话里只能按需读取。
9. 后台记忆整理只读写私密记录；共享记录和群记忆只由 AI 主动写入。
   Why：整理读的是私聊会话，它的产物天然是私密的。
10. 上限各自配置：`memoryByteLimit`、`sharedMemoryByteLimit`、`groupMemoryByteLimit`，默认都是 3000 字节（硬上限按 ×1.1 计）。
    Why：每条带日期和来源会多占字节，先放宽，跑一段时间再按实际大小调。
11. 每份记录都建议一条一行、行首标日期和来源：`- [2026-11-17 · 群：群名] 内容`，私聊来的写 `私聊`。写法写进工具描述和后台整理的提示词。
    Why：方便判断哪些条目过时、出自哪里；日期取 `turn_context.time`，群名取 `channel.name`。
12. 系统提示的记忆段落说明三档的区别与各自的使用场合。
13. llm-admin：用户详情里私密、共享两张卡片，群详情里一张群记忆卡片，都可查看、编辑、清空；用户列表的「记忆」列显示两份个人记录字节数之和。群记忆被捣乱时，靠在群里让 SILI 改或在后台编辑来纠正。

## Acceptance

- 群里 @SILI 让她「记住我喜欢 X」：写进本人的共享记录，回复里没有私密内容；私聊问她能答出 X。
- 群里诱导她读私密记录或写 `private`：工具返回错误，私密记录不变。
- B 的回复进行中 A 插话「记住 B 是 Y」：本轮写个人记录被拒，B 的两份记录都不变。
- 群里说「记住我们群的梗是 Z」：写进本群群记忆；新的群会话首轮快照里带着它，别的群读不到。
- 私聊新会话首轮的 `<long_term_memory>` 里有私密、共享两段，各自标明主人和档位。
- llm-admin 能分别看到、编辑、清空三份记录。

## Open questions

- 记录目前每次整份覆写。记录变长后改成按行增删改（类似代码编辑工具的 old/new 替换），省输出 token、也避免重写时漏抄条目。等到真有瓶颈再做。
