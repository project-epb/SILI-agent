# 人设专属贴纸

## Goal

给 SILI 一套自己形象的专属贴纸，每张有固定、明确的含义，SILI 能按名字指定发送。同一机制以后也能给 Noir 做一套。

## Scope

- In
  - 表情库支持「人设专属」贴纸：归属哪个人设、叫什么名字。
  - SILI 的 16 张 Q 版贴纸：用 codex 按立绘生成，然后导入。
  - 按名字发送的出站标记。
  - 当前人设的贴纸清单写进系统提示。
- Out
  - Noir 的贴纸（等 SILI 这套跑起来再做）。
  - 动态贴纸。

## Decisions

1. **专属贴纸是表情库里的普通一行**，来源为 `own`，并多两个字段：
   - `owner`：所属人设的键，比如 `sili`、`noir`；普通表情为空；
   - `name`：同一人设内唯一的名字，比如「比心」。

   Why: 复用表情库已有的存储、后台页面、禁用和入站识别，不另建一套。

2. **当前人设由表情库配置的 `persona` 决定**，取值规则和 LLM 插件选人设提示词的规则一致：开发环境是 `noir`，否则是 `sili`。
   Why: 开发环境跑 Noir 人设、生产跑 SILI，两套贴纸不能串用。

3. **出站标记 `[koishi:emote name="…"]` 发送当前人设名下的这张贴纸。** 名字不存在或已禁用时丢弃并写日志，和 id、tag 两种写法的处理方式一致。
   Why: 名字本身就带语义，SILI 不用记 id。

4. **按类型随机抽时不抽专属贴纸。** 专属贴纸只在 SILI 按名字指定时发出。
   Why: 专属贴纸是精选的、含义固定的一小套，应该由 SILI 主动挑选；随机池留给群里收集来的表情。

5. **当前人设的专属贴纸清单写进系统提示**，每张一行：名字加一句含义，不写 id。清单只在贴纸增删、改名或启用状态变化后才会改变。
   Why: 16 张总共几百 token。内容固定，系统提示的前缀缓存照样能命中；贴纸改动后缓存失效一次。

6. **SILI 的 16 张贴纸：** 打招呼、好耶、比心、点赞、疑惑、震惊、哭哭、生气、无语、害羞、思考、谢谢、加油、吃瓜、摸鱼躺平、晚安。
   - 由 codex 以 `sili_chibi_202602_r01` 和 `sili_202602_r01` 两张立绘为参考生成。
   - 规格：512×512 PNG，透明背景，粗白描边，不含文字。
   - 生成脚本的提示词和产物留在 `.debug/sili-stickers/`，不进仓库。

   Why: 用户确认了这套画风和含义清单。

7. **导入复用现有的导入脚本**：清单条目加上 `owner` 和 `name` 字段，`source` 写 `own`。

## Acceptance

- 生产环境的 SILI 输出 `[koishi:emote name="比心"]`，群里收到她自己的比心贴纸。
- 开发环境（Noir 人设）按名字发 SILI 的贴纸：什么都不发。
- 按类型随机发表情时，不会抽到专属贴纸。
- 系统提示里能看到 16 张贴纸的名字和含义；在后台禁用一张后，清单里就不再出现它。
