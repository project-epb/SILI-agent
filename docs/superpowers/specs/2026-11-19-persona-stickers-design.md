# 人设专属贴纸

## Goal

给 SILI 和 Noir 各配一套用她们自己形象画的专属贴纸，每张有固定、明确的含义，她们能按名字指定发送，而且优先用这套。

## Scope

- In
  - SILI 和 Noir 各 16 张 Q 版贴纸：用 codex 按立绘生成，上传到 CDN。
  - 一份按人设区分的贴纸清单配置。
  - 按名字发送的出站标记。
  - 把清单写进系统提示。
- Out
  - 动态贴纸。

## Decisions

1. **专属贴纸是配置，不进表情库。** `sticker-pool` 插件的 `personaStickers` 配置是一份 `{ name, meaning, url }` 列表。它不存数据库、不经过识图打标、不参与随机抽取，也不在后台页面里出现。各人设的清单写在 `src/plugins/sticker-pool/persona-stickers.ts`。
   Why: 这套贴纸由用户精选，含义是事先定好的，是一等公民；走表情库那套收集流程只会多出无用的步骤。

2. **装哪一套由运行的人设决定**：开发环境装 `noir` 的清单，否则装 `sili` 的。这条规则和 LLM 插件选人设提示词的规则一致。
   Why: 开发环境跑 Noir 人设、生产跑 SILI，两套不能串用。

3. **文件放在 CDN 上**，路径为 `artworks/<人设>/stickers/<英文名>.png`，比如 `https://r2.epb.wiki/artworks/SILI/stickers/heart.png`。上传时显式设置 `Content-Type: image/png`。发送时走 Cloudflare 图片缩放：`/cdn-cgi/image/width=200,format=png/<路径>`。
   Why: 人设的立绘本来就放在 R2 的 `artworks/<人设>/` 下；贴纸放在同一处，换图只需要覆盖文件。512px 的原图在 QQ 里显示太大；缩到 200px 后体积从约 230 KB 降到约 20 KB，透明背景也保留。

4. **出站标记 `[koishi:emote name="…"]` 发送当前人设清单里同名的那张。** 名字不存在时丢弃这个标记并写日志，处理方式和 id、tag 两种写法一致。
   Why: 名字本身就带语义，不需要记 id。

5. **清单写进系统提示**，接在表情包那一节后面，每张一行写「名字：含义」，并说明含义明确时优先用专属贴纸，其次才按类型随机。
   Why: 16 张总共几百 token。配置是固定的，系统提示的前缀缓存照样能命中。

6. **SILI 的 16 张贴纸：** 打招呼、好耶、比心、点赞、疑惑、震惊、哭哭、生气、无语、害羞、思考、谢谢、加油、吃瓜、摸鱼躺平、晚安。
   - 由 codex 以 `sili_chibi_202602_r01` 和 `sili_202602_r01` 两张立绘为参考生成。
   - 规格：512×512 PNG，透明背景，粗白描边，不含文字。
   - 生成用的提示词和原始产物留在 `.debug/sili-stickers/`，不进仓库。

   Why: 用户确认了这套画风和含义清单。

7. **Noir 的 16 张贴纸走雌小鬼路线：** 打招呼、嘲笑、比心、点赞、疑惑、震惊、假哭、生气、嫌弃、嘴硬害羞、坏主意、勉强道谢、加油、吃瓜、摸鱼、晚安。其中「摸鱼」画的是抱着一条大鱼在摸，是给群主「小鱼君」的彩蛋。以 R2 上 `artworks/noir/` 里的 `noir_chibi_202610_a` 和 `noir_202610_a_alpha` 为参考，规格与 SILI 那套相同；生成产物留在 `.debug/noir-stickers/`。
   Why: 用户要的是「小贱贱的雌小鬼表情包」，所以 SILI 那套里的好耶、无语、思考、哭哭，在这里换成了嘲笑、嫌弃、坏主意、假哭。

## Acceptance

- 生产环境的 SILI 输出 `[koishi:emote name="比心"]` 时，群里收到她自己的比心贴纸。
- 开发环境（Noir 人设）输出 `[koishi:emote name="嘲笑"]` 时，群里收到 Noir 的嘲笑贴纸；输出 SILI 独有的名字（比如「好耶」）时，什么都不发。
- 生产环境的系统提示里能看到 16 张贴纸的名字和含义。
