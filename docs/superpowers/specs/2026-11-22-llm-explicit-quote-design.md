# SILI 回复由模型显式指定引用

## 目标

群聊一轮可以收到多人的插话。回复和进度消息默认直接发送，模型需要指明回复对象时可以指定那条群消息。

## 决策

- 模型用 `[koishi:quote id="…"]` 请求引用。每个模型分段只接受段首的第一个引用标签，段首可有空白。无效或重复的标签从正文移除。
- `[koishi:msg_break]` 开启新段，也开启一次指定引用的机会。普通换行、按长度自动切段和工具调用时的刷出都延续当前段，防止续段重复引用或意外改变回复对象。
- 每条用户输入的 `turn_context.message_id` 对应该条消息本身，插话与积压消息也携带各自的 ID。发送时按当前平台、机器人和频道核验引用目标，使用消息记录中的真实 ID。
- `read_channel_history` 读取已存历史时，在每条消息前标出该条的 `message_id`。引用历史消息时可直接使用这个 ID。
- 进度、错误与调试输出默认直接发送。每次有效引用只附到该段首个实际发出的消息，QQ 被动发送凭据仍由原会话负责。

## 验收

- 默认回复、进度和自动续段发送时没有 QQ 引用。
- 两条由显式分段符隔开的消息可以各自引用一条群消息，包括插话。段中、重复或找不到当前频道目标的引用标签不会发给用户。
- 同一批流式输出含多个分段符时，逐段发送，各段使用自己的引用。
- 历史工具列出的每条消息都能通过自己的 ID 引用，即使该条消息本身也带了引用。
