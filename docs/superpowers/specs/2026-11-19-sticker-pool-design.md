# 表情库

## Goal

给 SILI 一套表情包，让她既能看懂群友发的表情，也能自己发表情。被逗笑、无语、纯表态的时候，只甩一张表情就是最像人的回法。

## Scope

- In
  - 表情库的数据模型，以及启用、禁用、拒绝三种状态。
  - 三个来源：后台上传；从群聊里自动收集；QFace 的 QQ 系统表情，离线转成 gif 后导入。
  - 视觉模型给每张表情打类型标签、写描述。
  - 入站：群聊里已入库的表情，在 SILI 的上下文里改写成表情占位；QQ 系统表情译成名称。
  - 出站：agent 输出 `[koishi:sticker]` 标记，发出去是一张表情图。
  - 人设里的表情使用礼仪。
  - 后台页面：上传、浏览、禁用和启用、修改标签与描述。
- Out
  - 一段话结束后按概率自动补表情。
  - 贴回应（emoji reaction）：官方 bot 不支持。
  - 已有的 `sticker` 指令（文字表情包生成器）不受影响。

## Decisions

1. **表情文件存在 `assets` 服务（`assets-s3`）里。** 这个服务指向 R2 存储桶 `cloud-epb`，生产用 `sili/v4_prod/` 前缀，开发用 `sili/v4_dev/` 前缀，公开地址是 `r2.epb.wiki`。数据库只记元数据和 URL。
   Why: v5 已经装了这个服务，生产和开发环境的路径前缀互相隔离，上传后直接返回公开 URL。实测 QQ 官方接口能正常从 `r2.epb.wiki` 拉取图片。

2. **数据模型：一张表情一行，用图片的 SHA1 作为身份。** 字段如下：

   | 字段 | 说明 |
   | - | - |
   | 短 id | 给 agent 引用 |
   | `sha1` | 图片身份 |
   | 来源 | `upload`、`harvest` 或 `qface` |
   | 状态 | 见下表 |
   | 类型标签 | 1 到 3 个 |
   | 描述 | 一句话，只描述画面 |
   | 文件 | URL、MIME 类型、宽高、是否动图 |
   | 统计 | 被群友发过几次、被几个人发过、出现在哪些群、SILI 发过几次 |
   | 时间 | 创建时间、更新时间 |

   状态有四种：

   | 状态 | 含义 |
   | - | - |
   | `candidate` | 正在累计出现次数，还没下载 |
   | `active` | 已入库，可用 |
   | `disabled` | 人工禁用 |
   | `rejected` | 视觉模型判定不是表情包 |

   只能禁用，不能删除。`disabled` 和 `rejected` 的记录永久保留：SILI 不会发它们，同一张图再出现时也不会被重新收集或重新判定。
   Why: 删掉一条记录，下次同一张图又会被自动收进库。用户要求只能禁用。

3. **群聊里一张图片的身份，直接取 QQ 图片 URL 里的 `fileid`。** 把 `fileid` 按 base64url 解码后，`0x12 0x14` 之后的 20 个字节就是原图的 SHA1。
   Why: 实测生产群聊最近的 57 张图片，下载原图计算 SHA1，57 张全部与这个摘要一致。这样不下载图片也能统计一张图出现了几次。

4. **自动收集的规则：** 一张图片满足下面两个条件，就成为候选：
   - 带 QQ 的表情标记 `faceType=6`；
   - 在所有群里累计出现 3 次以上，或者被 2 个以上的人发过。

   一旦成为候选，立即从刚收到的这条消息的链接下载原图，交给视觉模型判定：是表情包就打标签、写描述、转存到 `assets`，状态设为 `active`；不是就设为 `rejected`。
   Why: 以表情形式发出的图，QQ 会自动加上 `faceType=6` 标记，生产数据里 221 张图中有 64 张带它。被反复发送说明这张图是群里常用的。QQ 图片链接几个小时内就会过期，所以必须用刚收到的那条消息的链接立即下载。

5. **自动收集有总开关和每日上限，都在后台页面设置。** 设置存在数据库里，代码里只给默认值：
   - 默认关闭；
   - 每日最多入库多少张，默认 30；
   - 每日识图最多消耗多少 token，默认 50,000。

   按北京时间的自然日计数，每次识图后累加实际消耗的 token；两个上限触到任意一个，当天就停止识图。还没处理的图片保持 `candidate` 状态（只计次数，不下载）；等到额度恢复以后，它再一次出现时才会处理，那时会用新消息里还没过期的链接下载。后台上传的图片不受上限限制，但消耗的 token 照样计入当天的统计。后台页面显示当天已经入库几张、消耗了多少 token。
   Why: 用户要求能手动开关自动收集，并给每天的识图量设上限。v5 的插件配置写在代码里，在控制台改了也不会保存，所以开关和上限要放进数据库，在后台页面上改。

6. **视觉模型用 `deepseek-v4-flash`，一张图调用一次。** 调用时关闭 thinking，开启 JSON 输出，动图只取第一帧，缩到 512px 以内再发。输出 JSON：`{"is_sticker": bool, "tags": [...], "desc": "..."}`。
   - `desc` 只描述画面（主体、表情、动作、画风），不超过 20 字，不写用途。
   - `tags` 从固定的类型表里选 1 到 3 个。
   - 动图取若干帧。
   - 后台上传的图也走同一个判定，但跳过 `is_sticker` 这一项。

   提示里要禁止滥用「其他」：只有其余类型都不贴切时才能选它。
   Why: 照搬橘波特的分工：画面描述和情绪类型分开写，两者都更好检索。选模型的依据是一轮实测：55 张真实群聊图片，其中 26 张是人工认定的表情包。
   - `deepseek-v4-flash`：漏判 1 张（纯文字的「不算滥权」），没有误判；P50 0.9 秒；平均输出 26 个 token；每张约 ¥0.0006。
   - `qwen3.8-omni-flash`：漏判 2 张，没有误判；P50 6 秒；平均输出 431 个 token；每张约 ¥0.0015。

   两者的描述质量相当，各有个别看错颜色的地方。DeepSeek 的问题是爱给「其他」标签。
   Rejected: `qwen3.8-omni-flash` —— 准确率没有优势，却慢了 6 倍多、贵了一倍多。

7. **类型表写成代码常量：** 通用、开心、大笑、无语、疑惑、惊讶、生气、委屈卖惨、赞同、拒绝、晚安、其他。人设提示和视觉判定共用这一张表。
   Why: 类型表要先在实际使用中调稳，再考虑做成可配置的。

8. **入站改写。** 群聊消息里出现 `active` 的表情时，在 SILI 的上下文里改写成 `[表情包 id="…" alt="…"]`。QQ 系统表情（`faceType=1`）按 QFace 的名称对照表译成 `[QQ表情:名称]`。三处共用同一个改写函数：
   - chat 的输入
   - `read_channel_history` 工具
   - 隐式接话分类器的格式化器

   名称对照表由脚本从 QFace 的 `_index.v2.json` 生成，作为一份 JSON 放进仓库。
   Why: SILI 现在看到的是一串图片链接和转义过的 `faceType` 文本，读不懂。改写成带 id 的占位以后，SILI 还能顺手复读群友刚发的表情。

9. **出站标记 `[koishi:sticker id="…"]` 和 `[koishi:sticker tag="…"]`。** 这两个标记在 `sanitizeAgentOutput` 的白名单里新增一个分支处理：
   - `id`：发出这张表情；
   - `tag`：从这个类型的 `active` 表情里随机挑一张发出；
   - id 不存在或已禁用、类型下没有表情：丢弃这个标记并写日志，不把标记原文发出去。

   整条回复只有一个标记时，发出去就是一张孤零零的表情。
   Why: 沿用现有的 `[koishi:img]` 输出协议。按类型发不需要先调工具，省掉一轮往返。这一版不做表情搜索工具：agent 能拿到的 id 来自群友刚发过的表情，其余情况按类型发就够了。

10. **人设里加入表情使用礼仪**，写在系统提示的输出格式那一节：
   - 表情是调味，不是回复：不要每句都挂，不要连发，一个话题里偶尔一张。
   - 被逗笑、无语、纯表态、接不上话的时候，可以只发一张表情，一个字都不写。
   - 表情都是自己发的，被问起来就按自己的语气回答。

   Why: 搬用橘波特踩过坑之后的写法。表情发多了会刷屏，而说出「是系统发的」会打破人设。

11. **QFace 的表情离线导入，只导入用户手动挑选的那些。** 用一个一次性脚本，按用户给出的 emojiId 列表把 apng 转成循环播放的 gif（带透明背景），然后作为 `qface` 来源入库，标签按名称手动整理。
    Why: 实测官方 bot 发 apng 只会显示第一帧，gif 才会动。core 镜像里没有 ffmpeg，所以只能离线转换。全部导入会让按类型随机抽到冷门表情。

12. **后台页面做成一个 koishi console 插件**，功能有：上传（会自动打标签）、按来源/状态/类型筛选浏览、禁用和启用、修改标签与描述，以及自动收集的开关、每日上限和当天用量。

## Acceptance

- 在后台上传一张图，几秒后它带着标签和描述出现在列表里；禁用后 SILI 不再发它。
- 同一张表情被 2 个人在群里发过后自动入库；一张被反复转发的截图会被判为 `rejected`，以后再出现也不会重新判定。
- 群友发了一张已入库的表情，SILI 收到的上下文里显示为 `[表情包 id alt]`；QQ 系统表情显示成 `[QQ表情:名称]`。
- agent 输出 `[koishi:sticker tag="无语"]`，群里收到一张无语类的表情图；如果 id 不存在，什么都不发，也不会把标记原文发出去。
- QFace 导入的 gif 表情在 QQ 里会动。
- 自动收集默认关闭；在后台打开后，当天入库数或识图 token 触到上限就停止识图，第二天恢复；后台能看到当天的用量。
